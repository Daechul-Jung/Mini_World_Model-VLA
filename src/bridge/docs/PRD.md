# PRD: Bridge -- VLA x World Model

*Private. Gitignored.*

---

## Goal

The project's headline claim: **post-train a VLA with RL inside environments
generated by the world model, and show it beats behaviour cloning when measured
in a real simulator.**

Plus the reverse direction, which is less developed: use the VLA to improve the
world model.

This is the only package that imports both projects. Neither imports the other.

---

## The three problems this package exists to solve

Stated plainly, because each is a genuine open problem and none is plumbing.

### 1. Action space mismatch

A Genie-style world model is driven by 8 discrete latent codes discovered
without supervision. A VLA emits a continuous 4-7 DoF action in physical units.
Nothing in either model's training connects them.

Three routes, in `action_space.py`:

| Route | How | Cost |
|-------|-----|------|
| Learned projector | fit robot action -> latent code on paired data | cheap, lossy; `fit()` reports lift over chance, and near-chance means the approach is dead |
| **Robot-conditioned dynamics** | train stage C with `action_kind="robot"` on OpenX so no translation is needed | needs action-labelled video; **recommended** |
| Unified conditioning | one dynamics model taking latent code *and* robot action, with modality dropout | unexplored, most interesting |

**Current recommendation: route 2.** `configs/world_model/genie_small_openx.yaml`
does it. Latent actions are the right tool for unlabelled room video, not for
robotics.

### 2. Reward without ground truth

Inside a world model there is no object pose, no contact sensor, no success flag
-- only generated pixels. `rewards/` is a menu of approximations:

| Reward | Signal | Fails when |
|--------|--------|-----------|
| `goal_image` | embedding distance to a goal frame | a policy moves the camera to make the scene *look* right without touching anything |
| `progress` | VIP/LIV time-contrastive value | trained on data unlike imagined frames |
| `vlm_judge` | a VLM scores the frame | slow, unreliable on blurry generated frames |
| `dynamics_prior` | world-model likelihood | rewards *predictable* behaviour, not *successful* behaviour |

Two rules the contract enforces: every reward reports `uncertainty`, and
`EnsembleReward` can subtract disagreement from the total so the policy is pushed
toward regions where the rewards agree.

**Start with `goal_image` in `delta` mode.** It needs no training and gives the
baseline everything else must beat.

### 3. Two exploitable learned models

RL against a learned reward inside a learned world model has two things to hack.
The policy will find actions that are physically impossible and that the dynamics
model happens to score well. Mitigations, all partial and all on by default:

- KL penalty to the BC policy (`kl_coef > 0`; `RLAlgorithm` makes it explicit).
- Short episodes (`max_steps: 16`, not 200).
- Reward ensembles with a disagreement penalty.
- **Periodic re-validation in a real simulator.** This is the one that actually
  catches it. In-dream return is not a result.

## Success criteria

- [ ] **B1** `WorldModelEnv` produces a rollout with a reward signal that is not
      constant.
- [ ] **B2** The reward correlates with success on *real* held-out episodes.
      Measure this before optimising against it.
- [ ] **B3** A PPO/GRPO update runs without the policy diverging.
- [ ] **B4** In-dream return improves.
- [ ] **B5** **Simulator** success rate improves over the BC policy. Only this
      counts as the result.
- [ ] **B6** The gap between in-dream and simulator improvement is measured and
      reported. That gap is itself a finding.

---

## Out of scope, for now

- Real hardware.
- Training the world model and the VLA jointly. Two learned models, one loss, no
  ground truth -- there is no way to attribute failure.
- Using the VLA to improve the world model. Real idea, no concrete mechanism yet;
  the obvious candidate is using policy features as auxiliary supervision for the
  dynamics model. `research/030_vla_improves_world_model.md`.

---

## Open questions

1. Does a VLA trained on sharp real frames behave the same on tokenizer
   reconstructions? Unmeasured, and it invalidates everything downstream if the
   answer is no. -- `research/012_reward_on_imagined_frames.md`
2. How long can an imagined rollout be before its reward is noise? Related to the
   world model's `psnr_decay`; there should be a horizon beyond which experience
   is actively harmful.
3. Is in-dream RL better than simply generating more BC data with the world model?
   The cheaper baseline, and it must be run first.
